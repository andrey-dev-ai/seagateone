# Gate One LTD — seagateone

Рабочая версия сайта с пятью языками: EN / RU / UK / DE / AR. Украинский, немецкий и арабский добавлены; арабский интерфейс использует RTL. Морской стиль, исходные изображения и заявленные данные о судне сохранены.

## Проект и публикация

- [Репозиторий GitHub](https://github.com/andrey-dev-ai/seagateone).
- Vercel: проект `seagateone`, команда `andreumodus-7393s-projects`.
- [Рабочий публичный сайт](https://www.gateone.ltd).
- [Отчёт аудита](docs/audit-2026-10-05.md).
- Ветка изменений: `preview/multilingual-audit`.

Production не обновляется до одобрения preview владельцем. В `vercel.json` автоматические деплои из `main` отключены. Это намеренная защита на время восстановления и проверки. В первоначально пустом репозитории `main` содержит только защитную конфигурацию; полный проект находится в ветке изменений до её одобрения.

Подключение репозитория к существующему Vercel-проекту требует проверки в Project Settings → Git. Не создавать другой проект и не менять домены для обхода отсутствующего доступа. На момент подготовки подключение Vercel в агенте возвращало пустой список команд; создание онлайн-preview пока не подтверждено.

## Локальный запуск

Проверено: Node.js 24.12.0, pnpm 11.19.0. Node 24.x соответствует настройке проекта Vercel. Используйте рабочую папку на диске D: согласно вашим локальным правилам.

```powershell
git clone --branch preview/multilingual-audit https://github.com/andrey-dev-ai/seagateone.git D:\AI\seagateone
cd D:\AI\seagateone
pnpm install --frozen-lockfile
pnpm dev
```

Открыть [localhost:3000](http://localhost:3000). Для production-проверки:

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm audit
pnpm start --port 3001
```

В отдельном терминале из той же папки:

```powershell
pnpm test:e2e
```

Браузерные тесты используют установленный Microsoft Edge. Для другого адреса задайте `$env:TEST_BASE_URL='http://localhost:3002'`; для другого установленного браузера — `PLAYWRIGHT_CHANNEL`. Результаты создаются в `playwright-report/`, `test-results/` и `docs/screenshots/` и не попадают в Git.

## Что редактировать

| Файл | Назначение |
| --- | --- |
| `content/en.json`, `ru.json`, `uk.json`, `de.json`, `ar.json` | Все тексты, title/description, alt и доступные названия |
| `content/company.json` | Проверенные публичные email, телефон и адрес |
| `public/gate-one/index.html` | Исходный шаблон разделов; сервер переводит его по data-i18n |
| `public/gate-one/styles.css` | Основной фирменный стиль |
| `public/gate-one/enhancements.css` | Адаптивность, RTL, контраст, меню и доработки |
| `public/gate-one/site.js` | Мобильное меню, окна изображений, сохранение языка и якоря |
| `lib/site.mjs` | Серверная сборка переведённого HTML, проверка контактов |
| `app/[locale]/page.tsx` | Языковые страницы и multilingual SEO |
| `proxy.ts`, `app/layout.tsx` | Безопасное определение lang/dir по маршруту |
| `app/sitemap.ts`, `app/robots.ts` | Sitemap и правила индексирования |
| `tests/` | Регрессионные и браузерные проверки |

Старые `public/gate-one/app.js` и `config.js` сохранены как часть восстановленного оригинала, но новые языковые страницы их не запускают. Контакты теперь редактируются только в `content/company.json`.

Новые ссылки имеют вид `/uk#vessel`, `/de#company`, `/ar`. Старое `/?lang=ru#vessel` поддерживается через перенаправление. Язык сохраняется cookie; явная ссылка всегда имеет приоритет. Cookie содержит только код языка, не секрет.

При добавлении текстового элемента добавьте одинаковый ключ во все пять словарей и запускайте тесты. HTML в словарях — доверенные версии из Git; нельзя подставлять туда пользовательский ввод или непроверенные данные CMS.

## Логотип

Используется монограмма G1 по предоставленному владельцем изображению. Прозрачная версия подготовлена встроенным инструментом обработки изображений по запросу «выделить существующую монограмму, сохранить силуэт и пропорции, убрать фон и остальные элементы». Отдельно подготовлен квадратный значок по варианту в правом нижнем углу исходного изображения.

- `public/gate-one/assets/gateone-mark.png` — мастер PNG с прозрачностью.
- `public/gate-one/assets/gateone-mark.webp` — лёгкий файл для шапки и подвала.
- `public/gate-one/assets/gateone-app-icon-master.png` — мастер значка.
- `public/gate-one/assets/gateone-app-icon-512.png` — крупная иконка.
- `public/icon-light-32x32.png`, `icon-dark-32x32.png`, `apple-icon.png` — размеры для браузера и телефона.
- `public/icon.svg` — самостоятельная SVG-оболочка с встроенным растром, не восстановленный векторный оригинал.

Ресайз и экспорт не меняют геометрию подготовленного мастер-файла. Белый знак на тёмном сайте получается CSS-фильтром; буквы G1 и название GATE ONE LTD не зеркалятся в RTL. Для печати и идеально точного воспроизведения фирменной типографики лучше получить официальный SVG/AI/PDF исходник: приложенный растровый референс не является вектором.

## Контакты и содержание

Email, телефон и адрес пока пустые: их нельзя выдумывать. Можно указать только подтверждённые владельцем сведения. Раздел контактов показывается при наличии хотя бы одного корректного значения, включая один адрес без телефона.

Сохранены факты: одно собственное сухогрузное судно, 2014 год постройки, тоннаж 5 000 тонн. Не уточняйте DWT/GT, название судна, IMO, маршруты, офисы или достижения без исходных подтверждений. Изображения — иллюстрации, созданные ИИ, а не фотографии реального судна. Предупреждение переведено на все языки.

Переводы подготовлены и технически проверены; перед публичным выпуском рекомендуется редактура носителями языка, особенно морской терминологии DE/AR.

## Доступы и секреты

Для обычной работы сайта environment variables не требуются. Нужны права записи в GitHub и права деплоя именно в существующий Vercel-проект. Настройка доступа и подключение Git управляются владельцем в GitHub/Vercel.

Нельзя коммитить `.env*`, `.secrets/`, токены, ключи, пароли, папку `.vercel/`, `.next/`, `node_modules/` и архивы восстановления. Новые секреты храните только в личном закрытом хранилище владельца, не в README. Публичная конфигурация контактов также не является местом для ключей.

## Перед production

1. Проверить отчёт аудита, все пять языков, RTL и действительные контакты.
2. Убедиться, что код ветки проверен онлайн в Preview, а не только на localhost.
3. Получить явное одобрение владельца.
4. Только после этого включить разрешённый production-workflow и объединить изменения в `main` либо выполнить согласованный production-деплой.
5. Проверить реальные домены, перенаправления, метаданные, контакты и аналитику.

Старые Vercel-деплои и исходные файлы не удалены. Проверки не дают сертификат доступности и не заменяют инфраструктурный пентест. Локальные метрики загрузки не равны Core Web Vitals реальных посетителей.
